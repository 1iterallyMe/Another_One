# Итерация 2 — генератор, масштабы моделей, именование

## FIX-01 — нельзя было поднять генератор

**Симптом:** игрок наводится на генератор, но взаимодействие не появляется.

**Настоящая причина (не физика):** на одном GameObject (`1983262584500687189`)
висят **два** `IInteractable` — `GeneratorController` (заправка) и `PickupObject`
(поднять). `PlayerInteractor.UpdateFocus` брал **первый** найденный компонент и,
если его `CanInteract` возвращал `false` (нет канистры в руках), объект целиком
считался неинтерактивным. Масса (`m_Mass: 10` при `maxCarryMass: 20`) никогда не
была препятствием.

**Что сделано:** `Assets/Scripts/Player/Interaction/PlayerInteractor.cs`
— добавлен `ResolveInteractable(Collider)`: сначала основной `IInteractable`,
затем fallback на `IPhysicsHoldable` на том же объекте. Без аллокаций
(два `GetComponentInParent`), поэтому безопасно для `Update`.

**Проверено (Play Mode `Amir`):**
- `ResolveInteractable(BoxCollider генератора)` → `PickupObject`
- `BeginHold` → `IsHolding=True`, `HeldMass=10`, `IsDraggingHeavy=False`,
  `PlayerSpeedMultiplier=1`
- `Release` → `IsHolding=False`
- Console: 0 error

**Побочный выигрыш:** то же исправление лечит любой объект с несколькими
интеракторами (канистра/розетки/провод).

# Итерация 3 — bake Transform scale → ProBuilder-геометрия (зиплайн)

**Задача (пользователь):** «сам параметр размера должен быть 1, если хочешь больше —
увеличивай через ProBuilder». То есть все `Transform.localScale` = `(1,1,1)`,
а размер живёт в геометрии.

## Метод (важно для повторения)

1. `PrefabUtility.LoadPrefabContents(path)` → работа с ассетом без открытия stage.
2. Для каждого `Transform` с не-1 масштабом, **обход сверху вниз**:
   - перенос масштаба на детей: `child.localPosition *= s`, `child.localScale *= s`
     (иначе дети «съезжают» — первая попытка дала delta 0.36 и была заблокирована);
   - бейк своего меша:
     `UnityEngine.ProBuilder.MeshOperations.MeshTransform.FreezeScaleTransform(pb)`
     → `pb.ToMesh()` → `pb.Refresh()`;
   - если `ProBuilderMesh` нет (например, корень `GameObject`) — только push в детей
     и `localScale = 1`.
3. Предохранитель: если `|Δ world bounds| > 1e-3` или остались не-1 — **не сохранять**.
4. `PrefabUtility.SaveAsPrefabAsset(root, path)` + `UnloadPrefabContents`.

**Важные нюансы, найденные по ходу:**
- `MeshTransform` лежит в namespace **`UnityEngine.ProBuilder.MeshOperations`**
  (а не `UnityEngine.ProBuilder`), поэтому прямой вызов компилируется только так.
- `pb.positions = list` бросает `Collection is read-only` — использовать
  `FreezeScaleTransform` / `RebuildWithPositionsAndFaces`, а не сеттер.
- `Renderer.bounds` **у префаб-ассета недостоверны**: ProBuilder не строит меш для
  ассета (`meshSyncState = Null`, `MeshFilter.sharedMesh = null` — это НОРМА).
  Единственная надёжная проверка — инстанс в **preview scene** с `ToMesh()/Refresh()`.
- Ложная тревога: я принял `sharedMesh == null` за свою регрессию и откатил
  `ZiplinePart1` по pre-image (файл восстановлен **побайтово**, вреда нет).
  После проверки через preview выяснилось, что это исходное состояние префабов.
