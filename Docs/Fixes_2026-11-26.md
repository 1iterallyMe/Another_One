# Исправления по итогам QA-прогона — 2026-11-26

Прогон: сцена `Amir`, редактор Unity 6000.3.10f1 + собранный билд StandaloneOSX.
Все правки — отдельными коммитами, чтобы каждую можно было откатить независимо.

| Баг | Серьёзность | Коммит | Суть |
|---|---|---|---|
| BUG-031 | критичный | `c589560` | Экран смерти не показывался (soft-lock) |
| BUG-032 | критичный | `c589560` | Полоска здоровья не отображалась и не обновлялась |
| BUG-033 | средний | откат рабочей копии | Из `Menu_Scene`/`Credits_Scene` пропали UI-объекты |
| BUG-034 | средний (только билд) | `ebb6056` | `Outline` падал на мешах кнопок (`isReadable is false`) |
| BUG-035 | средний (только редактор) | `77411eb` | Кнопки «Играть»/«Титры» не работали в Play Mode |

## BUG-031 — экран смерти не показывался

**Симптом.** При смерти игрока FPS и `PlayerInteractor` отключались (`OnDeath`), но экран не появлялся:
`Coroutine couldn't be started because the the game object 'Death_Screen' is inactive!`

**Причина.** В `Amir.unity` на объекте `Player/Canvas/Death_Screen` стоял override `m_IsActive: 0`.
Компонент `DeathScreen` при этом не инициализировался (`Awake` не вызывался), а `Show()` не мог запустить корутину.

**Исправление.**
- в сцене объект включён (`m_IsActive: 1`);
- `DeathScreen.Show()` дополнительно включает объект и переинициализирует `CanvasGroup` перед корутиной —
  защита на случай, если экран снова окажется выключенным.

**Проверка.** `hp = 0` → `Death_Screen.active = true`, `alpha = 1.000`, `interactable = true`,
`Time.timeScale = 0`, курсор разблокирован, кнопки Restart/Menu подключены.

## BUG-032 — полоска здоровья не работала

**Симптом.** `Health_Bar.fillAmount` всегда `1`, объект `activeInHierarchy = false`, ошибок в консоли нет.

**Причина.** `HealthBarUI` висел на объекте `Player/Canvas/Selection_Frame`, который был выключен тем же
override-ом `m_IsActive: 0`. `Start()` не вызывался → подписки на `PlayerHealth.OnHealthChanged` не было.

**Исправление.**
- `Selection_Frame` (чёрный фон 400×100) и `Health_Bar` (заливка) включены в сцене;
- `HealthBarUI` подписывается в `OnEnable()` и отписывается в `OnDisable()` — устойчиво к переключению активности;
- у HUD-элементов снят `raycastTarget`, чтобы полоска не перехватывала клики.

**Проверка.** `hp 100 → 70` даёт `fillAmount 1.00 → 0.700`; при `hp = 0` → `0.000`.

## BUG-033 — пропавшие UI-объекты меню и титров

**Симптом.** Не отображались строка «ВЫБЕРИТЕ ДЕЙСТВИЕ», номер версии, памятка управления,
полоса прокрутки титров; `MainMenu.statusText/versionText` и `CreditsRoll.progressFill/versionText` были `NULL`.

**Причина.** Незакоммиченные изменения сцены (`−711` строк) удаляли объекты `Menu Status`, `Version`,
`Progress Track`, `Progress Fill`, `Section Label`.

**Исправление.** Изменения откачены (`git checkout`), сцены приведены к коммиту `bc5e0d4`.

**Проверка.** `MainMenu.statusText = Menu Status`, `MainMenu.versionText = Version`,
`CreditsRoll.progressFill = Progress Fill`, `CreditsRoll.versionText = Version`.

## BUG-034 — `Outline` на кнопках только в билде

**Симптом.** В `Player.log` сборки шесть раз:
`Not allowed to access vertices on mesh 'Cube' (isReadable is false; Read/Write must be enabled in import settings)`.

**Причина.** `Outline` висит на всех 15 кнопках (`Button_*`, `Key_Button_*`, `Wall_Button_*`),
а меши `Cube`/`Cube.001` из `Assets/Art/Models/button.fbx` импортированы с `isReadable: 0`.
В редакторе не воспроизводится (меши уже в памяти), в билде — всегда.

**Исправление.** В `button.fbx.meta` включён `isReadable: 1` (Read/Write), ассет переимпортирован.

**Проверка.** Запуск собранного `.app`: `grep -c isReadable Player.log` → `0`.

## BUG-035 — кнопки меню в Play Mode редактора

**Симптом.** `[MainMenu] Сцена «Amir» недоступна. Добавь её в Build Settings.` — при том, что сцена есть.

**Причина.** В редакторе `Application.CanStreamedLevelBeLoaded("Amir")` возвращает `false`
(проверено: индекс сцены `0`, метод — `False`). В билде работало, редактор-прогон — нет.

**Исправление.** Добавлен `Assets/Scripts/UI/SceneLoadUtility.cs`: имя сцены резолвится в индекс
через `SceneUtility.GetScenePathByBuildIndex`, загрузка идёт по индексу.
`MainMenu.LoadScene` и `CreditsRoll.ResolveMenuScene` переведены на него.

**Проверка.** В Play Mode из `Menu_Scene` вызов загрузки `Amir` → активная сцена `Amir`.
